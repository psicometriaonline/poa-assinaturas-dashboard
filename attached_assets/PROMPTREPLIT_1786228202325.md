```bash
git fetch origin claude/dashboard-paid-model-kgvb4o
```

```bash

```

## Contexto — leia antes de mexer em qualquer métrica

A Psicometria Online Academy **não aceita mais cadastros gratuitos**. O dashboard foi
reescrito para o modelo 100% pagante. Não existe mais free-trial, funil de cadastro
gratuito, contagem de leads ou taxa de conversão cadastro → assinante.

**Não reintroduza nenhum desses conceitos.** Se algo parecer "faltando" (o menu Funil,
a página de Leads, a tag 401 do ActiveCampaign, a data de corte de março/2026), foi
removido de propósito.

### Regra de ouro do código de métricas

Toda métrica de assinatura sai de `artifacts/api-server/src/lib/subscription-sql.ts`.
**Não escreva SQL de MRR, churn ou assinantes ativos direto numa rota ou página.** Foi
exatamente isso que fez o dashboard antigo mostrar três taxas de churn diferentes em três
telas. O `metrics/overview.ts` apenas compõe `revenue.ts` + `churn.ts` +
`subscriptions.ts` — ele não recalcula nada.

Consultas que cortam por tempo devem ler o CTE `timeline`, nunca `subs` direto. O `subs`
inclui assinantes cuja data de saída é desconhecida; usá-lo numa série temporal faz o MRR
subir acima do valor real.

## Banco de dados

As migrações rodam sozinhas no boot (`artifacts/api-server/src/lib/migrations.ts`). Elas:

- adicionam as colunas `original_event` e `date_next_charge` (idempotente);
- normalizam `status = 'PAST_DUE'` para `'DELAYED'` — o KPI "Atrasados" lia um status que
  nenhum código escrevia, então vivia zerado;

Nenhuma tabela é apagada e nenhum dado é perdido. A tabela `leads_daily_snapshots` deixou
de ser usada; pode ficar onde está.

## Variáveis de ambiente

Nenhuma nova é obrigatória. Todas as existentes continuam valendo.

Opcional: `AC_MEMBERS_LIST_ID` — id da lista de assinantes no ActiveCampaign, usada para
atribuir a origem UTM das assinaturas. O padrão é `30` (Alunos - POA), então só defina se
a lista mudar.

Se o ActiveCampaign não estiver configurado ou não responder, a página **Aquisição**
degrada com um aviso em vez de quebrar. As demais páginas não dependem dele.

## O que esperar depois de subir

Novo menu: **Visão Geral · Receita · Assinaturas · Churn & Retenção · Aquisição ·
Tráfego · Perfil dos Assinantes**. O `/admin` continua funcionando, fora da navegação.

Os números **vão mudar em relação ao dashboard antigo, e isso é o esperado** — o antigo
estava errado em pontos específicos:

- O MRR histórico era reconstruído por soma acumulada e usava `last_event_at` (que recebe
  `NOW()` a cada evento) como data de saída, o que jogava todo assinante encerrado sem
  data no mês corrente e criava um degrau falso. Agora o MRR é medido ponto-a-ponto: o
  último ponto da série é igual ao MRR atual por construção.
- O churn era dividido pelo total de linhas da tabela, cancelados incluídos — a taxa caía
  sozinha conforme a base crescia. Agora o denominador é a base ativa no início do mês,
  então **a taxa de churn tende a aparecer mais alta, e essa é a correta**.
- O seletor de período era ignorado pela página de receita; agora vale para tudo.

Se aparecer uma nota de qualidade de dados no rodapé da Visão Geral ("N assinaturas
encerradas não têm data de cancelamento"), é informação intencional, não um bug: essas
assinaturas ficam fora da série temporal em vez de distorcê-la em silêncio.

## Duas limitações conhecidas (não são bugs)

1. **Expansão e contração de MRR não são calculadas.** O MRR usa o preço atual de cada
   assinante porque não há histórico de preço no banco. Somar uma série de expansão hoje
   seria dupla contagem. Para habilitar no futuro: gravar cada mudança de
   `mrr_contribution` numa tabela de histórico e compor o MRR a partir dela.
2. **Caixa (billings)** só existe a partir dos eventos `PURCHASE_APPROVED` recebidos via
   webhook. Meses anteriores à configuração do webhook aparecem zerados — é ausência de
   dado, não receita zero.
